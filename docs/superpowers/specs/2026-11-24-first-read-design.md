# First Read：VS Code 代码阅读扩展

## 范围与架构

首版是桌面 VS Code 的 TypeScript 扩展，仅处理语言 ID 为 `python` 或 `cpp` 的当前文本编辑器。专注模式与悬停解释独立启用，共用快照、语言服务适配器、OpenAI 兼容客户端和有上限的内存缓存。取源码时使用编辑器缓冲区，包括未保存内容，不读工作区其他文件。后续阅读目标、变量追踪和侧栏不在首版范围。

通过 VS Code 命令调用已安装语言扩展的 `DocumentSymbolProvider` 和 `SelectionRangeProvider`，不打包解析器、不强制特定厂商。小文件专注模式不需要语言服务；长文件没有可靠符号范围则提示启用语言服务并保持原亮度。悬停优先选择包含目标位置、形态合理且在预算内的语句范围；无法确定时改用当前行及有限邻近代码，不声称识别出了完整语句。符号可用于提供包围函数签名。

## 模型与边界

用户级设置指定服务地址与模型，使用兼容的 Chat Completions API，密钥由命令写入 `SecretStorage`，工作区不能指定发送端点。仅在可信工作区、功能已由用户启用且满足触发条件时发送源码。启用时告知用户源码发送至配置的服务；不记录源码、密钥或模型原文到日志。模型输出仅作为数据：专注结果解析为区间，悬停结果用纯文本展示，不执行输出或启用链接。

## 专注模式

通过命令面板或快捷键切换当前编辑器的专注模式。用 `setDecorations` 将非核心代码透明度降至 36%，核心代码保留原亮度。不改写源码、折叠或语法高亮。核心行应涵盖主要输入输出、改变行为的条件和分支、状态切换、副作用及关键配置；常规日志等非核心部分可以调暗。具有行为意义的错误处理不能一概调暗。

以实际请求源码预算区分小文件和长文件：小文件一次发送带位置的完整快照。长文件不预扫、不发送全文件目录。开启后监听可见范围：视口稳定 1.2 秒才分析，每次滚动重置计时，快速划过无需请求。选择与可见范围相交的函数或类，按预算纳入；单个符号超限时发送可见代码和外层签名，不能随预算截断后仍把遗漏的代码算作已分析。折叠或未传输的区域不因相邻行已分析而调暗。重复停留时复用已覆盖的区域，不再次请求；视口内若尚有未覆盖部分，只为未覆盖部分选择分析目标，允许发送必要的重叠上下文。

模型返回文件中的一基闭区间。严格验证输出及覆盖范围，合并合法重叠区间，只在实际送分析且验证成功的覆盖范围内计算补集；仅作上下文发送的签名不计入覆盖范围。无可靠区间、请求错误或缺配置时，新目标保持原亮度并显示简短提示。编辑、关闭专注模式或切换模型配置时清除受影响的装饰；每次应用结果前检查快照版本、模式状态及配置，旧结果不得重挂装饰。

## 悬停解释

默认关闭，独立于专注模式。只处理有代码的目标行。使用原生 HoverProvider；冷缓存以约 800 ms 总停留为目标，扣除 VS Code 的 `editor.hover.delay`，热缓存不加插件等待。发送完整语句（能可靠定位时）、少量相关邻近代码和必要签名；在原悬停行显示一句话，只解释可见源码所支持的作用，不猜测单位或外部定义。失效、错误或格式不合格时不显示解释，不弹出重复通知。

移开时取消尚未发送的等待；网络请求一旦发出，不因悬停取消、移开或编辑而中断，由客户端超时结束。有效响应可按原请求键入缓存；再次悬停同键复用在途请求。仅活跃且文档版本仍匹配的调用可以显示解释。

## 缓存与验收

缓存限定在扩展宿主生命周期内，不另存源码或解释到磁盘。专注记录包括准确快照、内容哈希、实际覆盖区域、核心区间和模型及提示词配置。内容与配置相同可直接复用；否则只在狭窄规则能确认是安全的位置变化时重映射，语义变更或映射不唯一时重新分析。比较端点为两份实际缓冲区，不依赖 Git。悬停按语言、实际目标语句、传输上下文、服务地址、模型和提示词版本去重。配置或凭据更换使旧缓存与在途结果失效。

用 Python RL 和 C++ 控制代码在 VS Code 验证：小文件一次分析、退出恢复、长文件快速滚过零请求、停留只分析对应区域、回滚不重发、缺少符号时不上传长文件、无效区间不调暗、未保存编辑后无错位、控制流修改重新分析。悬停验证跨行、短停留零请求、热缓存、发出后移开不取消、再次悬停复用及编辑后旧响应不显示。记录请求数、缓存命中、冷响应耗时、错位和遗漏的核心段；token 只记录服务实际返回的用量，不把缺失字段当作零。
